# 作品探索框架

## 已实现

- `/zh/works`、`/en/works`、`/fr/works` 独立作品探索页面。
- 六类作品入口：小说、电影、剧集、游戏、剧本杀、密室逃脱。
- 作品、人物、文化、地点四种浏览视图。
- 搜索、类别、资料语言、版本或体验语言、地区与排序写入 URL；切换界面语言保留查询条件。
- 所有类别的资料字段说明和真实空状态。
- 作品详情：封面与来源、独立作品介绍、资料网格、渠道、作品关系和来源。译名与可展开的版本列表并入资料字段。不存在或尚未发布的作品返回 404。
- 导航使用可用键盘操作的语言下拉菜单，保留当前作品及查询条件。
- 多语言名与别名、创作者关联、版本与获取渠道筛选的领域逻辑及测试。

当前支持真实来源导入，结果保存于 `.data/snapshot.json`；新克隆未运行导入时为空。没有演示作品、虚构评分、假收藏或假报名。测试用合成记录仅存在于 `tests`。云数据库尚未接入，来源和授权边界见 `docs/data-sources.md`。

## 模块边界

- `types.ts`：作品、人物、文化、地点、系列、版本、渠道、作品关系与来源结构。
- `config.ts`：六类作品及其展示字段、筛选值。
- `query.ts`：参数规范化、多语言检索、地区与语言匹配、安全外链及查询序列化。
- `repository.server.ts`：资料读取边界，从本地快照读取；后续替换为数据库查询。
- `components`：探索页与详情展示。路由不直接访问外部采集网站。
- `messages/catalog`：中英法三份同结构文案。

作品身份不随界面语言变化。版本通过 workId 连接作品；渠道可连接版本和具体地点。剧本或密室主题与门店分别建模。原作与改编分别拥有作品身份，通过关系连接。

“资料语言”要求对应语言的简介实际存在；“版本语言”不根据原作语言推断。地区与语言同时筛选时，必须在同一条渠道或其关联版本上成立，避免把法国法语渠道与中国中文渠道拼成“法国可获取中文版本”。

## 后续开发优先级

1. P0：确定来源及允许的获取方式；完成一个来源的字段映射和有效性验证。
2. P0：数据库结构与后台编辑；补充必填字段、来源记录、数据去重、翻译与版本规则。
3. P0：候选资料导入 → 人工审核 → 正式发布；先跑通少量真实作品。
4. P1：完善详情字段的本地化与单位、封面、分页、多字段检索、系列顺序和相关人物／地点详情。
5. P1：账号接入后实现真实清单、私人笔记与评价；明确剧透标记。
6. P2：新增数据来源、增量更新、渠道复查、失败重试与批量纠错。

采集器在 `jobs` 中独立执行，经验证和审核后写入资料库。不要通过让页面加载时直接抓取外站来填充内容。
