# 架构说明

## 当前骨架

单仓库 Next.js App Router + TypeScript + next-intl，npm 锁定依赖。界面样式使用普通 CSS，暂不引入额外组件系统。

- 页面层：`src/app`。
- 共享组件：`src/components`。
- 三语配置：`src/i18n` 与 `messages`。
- 业务模块：后续在 `src/features` 中按领域添加。
- 独立任务：后续在 `jobs` 中添加入口，复用服务端业务规则。

Supabase 是后续数据库、认证与存储的候选方案；本次没有创建云资源、连接数据库或启用真实认证。

作品探索已在 `src/features/catalog` 提供类型、查询逻辑、资料读取边界和展示组件；从 `.data/snapshot.json` 读取独立任务导入的真实数据。详情路由 `/[locale]/works/[id]` 仅为真实存在的记录渲染，不存在的作品返回 404。筛选使用 URL 参数，界面切换语言保留这些参数。详见 `docs/catalog.md` 和 `docs/data-sources.md`。

巴黎活动在 `src/features/events` 处理，使用服务器筛选与客户端 Leaflet 地图／列表联动。`src/features/ingestion` 负责外部来源规范化、来源状态、按确定 ID 合并和本地持久化；`jobs/sync.ts` 提供单次与循环更新入口。用户访问页面不触发采集。

GitHub 的日常 CI 与手动 Release 分开。发布时选择性启用 Next.js standalone，在 Linux 上打包并测试实际运行目录；数据与密钥不进入版本包。Sites 的公开演示部署使用独立适配副本，见 `docs/github-release.md` 与 `docs/deployment.md`。

GitHub Pages 演示站使用 `scripts/prepare-pages-demo.mjs` 生成独立前台源码副本：资料为显式公开快照，查询在浏览器执行，详情在构建时生成，不复制采集后台、凭据或私人内容。发布通过原生 Pages Actions，构建输出不提交 Git。当前套餐不支持私有仓库 Pages，发布仓库的可见性需由用户决定。详见 `docs/github-deploy.md`。

## 后续数据关系

- 作品、语言名称、出版或发行版本分别保存。
- 原作与改编、系列与单作通过关系连接。
- 私人记录、公开评价、公开或私密清单分别建模。
- 活动关联多部作品，报名记录独立管理。
- 活动日期保存时间点与 IANA 时区；界面语言不决定用户所在地区。
- 观看渠道区分地区，保留核对时间。
- 帖子和文章可以关联作品与活动。
- 来源、外部 ID、同步结果、候选修改及失败原因可追踪。

## 运行边界

浏览器 → 页面及服务端业务入口 → 数据库与存储。

定时调度 → 外部来源 → 清洗与匹配 → 审核或批准的更新规则 → 正式资料。

页面访问不依赖实时爬取。已有人工作出的修改不能被采集静默覆盖。新增作品和活动先进入审核流程。

## 权限与质量

匿名用户浏览公开资料；注册用户管理自己的记录与帖子；活动发起者管理自己的活动；管理者审核与维护内容。所有写操作均需在服务端校验身份、所有权与输入，数据库层同步限制访问。

报名采用原子容量检查和重复提交保护。外部活动的收藏、跳转与真正报名分别表达。

后续测试聚焦三语搜索、私人数据隔离、报名并发、剧透展示、数据去重和同步失败恢复。

## 初始骨架的检查

ESLint、TypeScript、Prettier、生产构建以及实际 HTTP 路由检查。当前没有业务数据库，因此不创建没有实际对象的业务测试。
